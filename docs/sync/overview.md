你在手機上記了一筆午餐，回到家打開電腦的網頁版，這筆帳已經在那裡了。換新手機時，登入之後所有帳本和歷史紀錄就回來了。這就是 BeeCount Cloud 的雲同步在做的事。

> 📱 App　💻 Web

## 為什麼這樣設計

這個版本把資料集中放在你的 BeeCount Cloud 伺服器上，而不是讓每台裝置各存一份、再手動上傳下載。這樣做有三個好處：

- 手機、平板、網頁看到的是同一份資料，不會有「哪一台才是最新」的問題。
- 換機、重灌都不怕資料遺失。
- 家人或朋友可以一起用同一本帳，見[共享帳本](./shared-ledger.md)。

為了確保只有被允許的人使用，App 啟動時會檢查登入狀態與授權金鑰，見[授權金鑰](./license.md)。

## 同步是怎麼運作的

1. 你在任何一台裝置記帳、修改或刪除，這個變更會先存在那台裝置上。
2. 有網路時，變更自動傳到伺服器，不需要手動按「上傳」。
3. 伺服器通知你的其他裝置，其他裝置把變更拉下來。通常幾秒內就看得到。
4. 如果同一筆資料在兩邊同時被改，以最後修改的那一次為準。

:::tip
一般使用時你不用做任何事，記帳就是同步。只有懷疑資料沒同步時，才需要看下面的檢查方法。
:::

## 離線時會怎麼樣

- **可以繼續記帳。** 沒有網路時記的帳先存在手機裡，連上網路後會自動補傳。
- **看不到其他裝置的新資料。** 要等重新連上網路才會同步進來。
- **授權有 7 天的離線期限。** 每次 App 連上伺服器確認授權有效後，可以離線使用 7 天。超過 7 天都沒連網，App 會顯示「需要連網驗證授權」並擋住使用，連上網路按「重試」就恢復。詳見[授權金鑰](./license.md)。
- **剛換新裝置時需要網路。** 第一次登入要把雲端的資料整份拉下來，資料多的時候請用 Wi-Fi，並等它跑完再離開 App。

## 怎麼檢查同步狀態

### 📱 在 App 上

1. 點底部的「我的」。
2. 最上面的「雲服務」會顯示目前連到的伺服器，例如「BeeCount Cloud v…」。
3. 下面的「同步」會顯示狀態：「已同步」「本機有更新」「雲端有更新」「未登入」或「狀態取得失敗」。
4. 點「同步」進入「雲同步」頁，可以看到：
   - 帳號（登入的 email）。
   - 「同步狀態」：「本地與雲端一致」或「偵測到差異，已自動同步」，以及目前帳本與全部帳本的交易、附件、預算、帳戶、分類、標籤筆數，格式是「本地 N · 雲端 M」。
   - 「未推送變更」：還沒傳到雲端的變更數量，連上網路後應該會歸零。
5. 在這一頁往下拉，可以重新做一次「深度檢測」，比對手機與雲端的差異。

### 💻 在 Web 上

Web 直接讀取伺服器上的資料，所以不需要另外同步。想確認伺服器是否正常，可以看頭像選單 → 「健康」，見[裝置與安全](./devices.md)。

## 同步不動時怎麼辦

1. 先確認手機有網路，而且「我的」裡顯示的狀態不是「未登入」。
2. 到「我的 → 同步」，往下拉做一次深度檢測，看「未推送變更」有沒有在減少。
3. 展開頁面上的「同步說明 · 為什麼有時同步不動？」，裡面有更多說明。
4. 還是不行，點裡面的「開啟日誌中心」，可以看到同步日誌，把錯誤訊息回報給管理員。

:::note 資料多的時候
第一次登入或換新裝置時的整份下載不能中途接續。中途斷網或 App 被系統關掉，會從頭再來，所以建議用穩定的網路等它跑完。日常記帳的同步則不受影響。
:::

## 注意事項／小提醒

- 如果「我的」裡顯示「狀態取得失敗」，而且 App 提示要更新版本，代表你的 App 版本低於伺服器要求，更新後即可。
- 登出再用另一個帳號登入，會先清掉這支手機上原本的資料，見[安裝與登入](../preface/install-login.md)。
- iCloud、WebDAV、S3、Supabase 這些備份方式在這個版本不是日常使用的路徑，見[其他備份方式](./other-backup.md)。
