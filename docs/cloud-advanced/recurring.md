# 週期性收支

> ⚠️ **僅 Cloud 版可用**：本頁功能是 BeeCount Cloud（自建服務端）獨有的進階功能，純 App 本機記帳沒有這個入口。

房租、訂閱費、保險費這類每月固定發生的收支，設一次規則後系統會自動幫你按週期產生交易，不用每個月手動記。

## 開啟入口

登入 Web 端後，右上角**頭像** → 「工具」分組 → **週期性收支**（`/app/recurring-rules`）。

![週期性收支列表](https://photo.pnsgzomf.synology.me/i/2026/08/11/6a79f909c6321.png)

## 建立規則

點「新增規則」，可設定：

| 欄位 | 說明 |
|---|---|
| 類型 | 支出 / 收入 / 轉帳（轉帳可用來做「自動扣繳」） |
| 金額、分類、帳戶 | 非轉帳規則**一定要選分類**——這類系統自動產生的交易不允許沒有分類；帳戶不能選「帳戶群組」這種純管理容器 |
| 頻率 | 每天 / 每週 / 每月 / 每年，可設定「每隔幾個週期」（例如每 2 週） |
| 進階規則 | 可選「每月固定第幾天」或「每週固定星期幾」這類更精確的排程 |
| 首次發生時間 | 第一筆交易何時產生 |
| 結束時間 | 不填代表長期規則 |

## 交易怎麼自動產生

- 有設定結束時間的規則，建立當下就會把整段區間的交易**一次全部產生好**。
- 沒有結束時間的長期規則，建立時只先產生未來一年份，之後由背景排程每天檢查、自動往後續產，確保永遠有未來一年的份量。
- 類型是「轉帳」的規則（例如信用卡自動扣繳）不會提前產生——會等到真正到期那一刻才即時產生一筆，而且會先檢查來源帳戶餘額夠不夠，不夠就先跳過、之後定期重試。

## 調整已產生的交易

- 每一筆已產生的交易都可以單獨改金額、改日期，改過的那一筆會被標記「已覆寫」，之後規則批次更新或續產時會自動跳過它，不會被覆蓋回去。
- 「終止未來週期」：把所有還沒發生的交易全部刪掉，規則本身停用，但已經發生過的歷史交易保留不動。

## 常見問題

**改了規則的金額，已經產生的交易會跟著變嗎？**
不會自動全部變。你可以在規則的「查看已生成交易」裡挑選某一筆，用「以此筆為準，更新之後所有交易」的方式批次修改該筆之後、尚未被單獨改過的交易。

**規則刪了，之前產生的交易也會被刪掉嗎？**
不會，刪除規則只影響規則本身和尚未發生的交易，歷史交易保留在帳本裡。
